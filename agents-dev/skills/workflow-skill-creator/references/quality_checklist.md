# 质量检查清单

创建完成后，逐项自检。此清单也适用于 review 现有流程编排 Skill。

## 结构检查

- [ ] SKILL.md 主体 < 200 行
- [ ] 每个 Step 框架文件独立且 < 100 行
- [ ] `references/step_frameworks/` 目录存在且每步一个文件
- [ ] `scripts/` 至少包含路径生成脚本
- [ ] `assets/` 包含 progress_template.md 和 output_template.md

## 进度文件检查

- [ ] 进度文件路径通过脚本生成（非手动拼接）
- [ ] 所有步骤间有明确的 `{progress_file_path}` 占位符传递
- [ ] 每个 step framework 开头有 `⚠️ 路径一致性要求` 警告块
- [ ] `references/progress_file_spec.md` 已按实际 skill 定制

## 执行规范检查

- [ ] 所有 Step 框架包含三阶段（校验→执行→验证）
- [ ] 每步有明确的完成标准和验收规则
- [ ] 命令是可复制执行的（无"参考命令"模糊指导）
- [ ] 每步要求 Edit 追加命令记录和执行结果到进度文件

## 前置门槛检查

- [ ] 输入参数列表完整（缺少时明确要求补齐）
- [ ] 每个参数有默认值或明确标注"需用户确认"
- [ ] 参数齐全后才允许进入 Step 1

## 依赖检查

- [ ] 依赖声明完整（外部 skills、MCP 工具、脚本路径）
- [ ] 所有引用的文件路径存在
- [ ] 脚本有 `--help` 和错误处理

## 触发检查

- [ ] description 以触发条件开头（"当用户...时应使用此技能"）
- [ ] 包含 ≥5 个中文触发关键词且覆盖多种说法
- [ ] 覆盖正式说法和口语化说法

## 输出检查

- [ ] 最终输出模板格式完整（如有标准化输出）
- [ ] 模板中的占位符清晰（用 `{变量名}` 标注）
- [ ] 占位符命名一致（同一变量在 SKILL.md 和模板中使用相同名称）

# 硬性边界与「不作为改写理由」

本文件合并自 [larashero3-dotcom/lieflat-less-ai-tone](https://github.com/larashero3-dotcom/lieflat-less-ai-tone)（MIT）的白名单约束。**深度指南默认模式（成稿清理）必须以本文件为最高优先级**，优先于 [pattern-catalog.md](pattern-catalog.md) 中偏创意的「注入灵魂」建议。

实测数据与被推翻的预设见上游 [RESEARCH.md](https://github.com/larashero3-dotcom/lieflat-less-ai-tone/blob/main/RESEARCH.md)，此处不收录全文。

## 有风格参考时先读它

若同一目录下有描述目标风格的文档（写作风格指南、语言特征分析、`语言DNA.md` 一类），先读再改，把它的句长分布、标点习惯和用词偏好作为判断依据。

**风格文档与本 skill 规则冲突时，以风格文档为准。** 那是目标作者的真实写法，不是 AI 痕迹。例如某作者本来就爱用破折号，就不要按破折号规则删掉。

## 硬性边界（最高优先级）

默认采用**白名单式改写**：只能处理 [validated-rewrite-rules.md](validated-rewrite-rules.md) 中明确列出的规范，以及 [pattern-catalog.md](pattern-catalog.md) 中与白名单一致、且未列入下方「不作为改写理由」的模式。不能凭一般写作经验扩大改写范围。

- 没有命中任何规则的句子必须**逐字保留**
- 一句话即使命中规则，也只能改动解决该问题所必需的部分；不得顺便润色、替换无问题词语、调整语气/详略/信息密度
- 对某处是否命中没有把握时，**保持原文**
- 文章结构不在处理范围内：标题层级、章节顺序、段落数量与顺序、列表、表格、引用和代码块的位置必须原样保留
- 除非用户另行明确要求，否则不能概括、扩写、删减观点或重组论证

### 信息守恒：不许新增，不许删减

原文的观点和事实必须完整保留。以下内容绝不能凭改写添加：

- 姓名、机构名、职务、地名
- 数字、比例、金额、时长、次数
- 日期、时间、先后顺序
- 引语、对话、别人的说法
- 引用来源、出处、链接
- 因果、动机、心理活动
- 任何原文没写的细节、场景或案例

反方向同样禁止：不能删掉原文的观点、结论、限定词和让步（「可能」「通常」「在某些情况下」「据说」）。把「可能提升」改成「提升」是篡改语气强度，不是去 AI 味。

判断办法：改写后的每个实词，都要能在原文里指出出处。指不出来就是新增，必须撤销。

「把抽象写具体」不是默认职责。原文抽象就让它抽象。仅允许把原文**已有**的具体数据提到概括词的位置，不允许自己造数据。

## 不改的情况

- 文章框架（见上）
- 对话体、口语体：本来就是自然表达
- 问句：正文问句、反问、问句小标题都不改（见下表）
- 文学性表达：散文、小说里的排比和比喻要按原有风格判断
- 体裁要求：学术、新闻、公文等不必强加「我/你」，也不必拆成短段落
- 代码块、外语段落
- 引用他人原文

## 不作为改写理由（硬约束）

以下特征看着像 AI 味，实测站不住，**不能据此改文字**：

| 特征 | 为什么不改 |
|------|-----------|
| 句长、段落长度不够参差 | 实测与人类写作无差别。不要为了制造节奏调句长或拆段落 |
| 单字虚词偏少（就/很/了） | AI 确实偏少，但方向是补不是删；补虚词无法验收，易把正式文改成口语 |
| 反复写全称、少用代词 | 实测人类比 AI 更常重复同一名词 |
| 被动句 | 抽象被动（「被认为／被视为」）远低于收录门槛 |
| 名词化、长句本身 | 现代汉语书面语的正常写法 |
| 正文里的「首先……其次」 | 与人类写作无差别；仅小标题通篇「一、二、三」编号才处理 |
| 句内同构排比 | 「提升效率，降低成本，优化体验」类人类用得不比 AI 少；只处理句间重复骨架 |
| 问句、设问、问句小标题 | 正文问句人类远多于 AI |
| 比喻本身、比喻独立成段 | 人类用得比 AI 多；只处理理想化拟人喻体 |
| 抽象名词配具体动词 | 「时间替他保管了细节」类两边都几乎不写 |

规则依据是**触发标记可定位**，不是主观「像不像人」。不要按「某个模型的味」套判断。

部分规范亦参考 [KKKKhazix/human-writing](https://github.com/KKKKhazix/human-writing)。

## 与 pattern-catalog / 「鲜活改写」的关系

| 模式 | 何时使用 | 约束 |
|------|----------|------|
| **成稿清理（默认）** | 用户要去 AI 味、保留信息与结构 | 本文件 + validated-rewrite-rules；未命中则不动 |
| **CLI 路径** | 批量/评分/`--seed` | 脚本按词库改写，可能比白名单更激进；定稿前通读 |
| **鲜活改写（可选）** | 用户**明确**要求注入个性、第一人称、创意重写 | 仍须信息守恒；不得编造事实；可参考 pattern-catalog「个性与灵魂」 |

默认不要为了「更有人味」强加人称、口语、短段落或虚构细节。

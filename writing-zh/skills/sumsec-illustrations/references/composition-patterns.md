# 构图模式与原创规则

## 基础结构类型

选择一种结构即可，不要混太多。

### Workflow 流程

适合：输入 -> 处理 -> 输出，内容生产，AI 工作流，自动化链路。

画法：左侧输入，中间黑色操作员或怪机器处理，右侧输出，橙色箭头表达主流向。

### 系统局部

适合：信息来源、过滤器、数据库、渲染器、agent 系统局部。

画法：只画 3-5 个核心模块，黑色操作员参与其中一个关键动作。

### 漏洞链路

适合：安全研究、攻击面、PoC、漏洞复盘、风险传递。

画法：把漏洞链路画成一串松动的管道、门锁、闸门或证据钉板。黑色操作员拿手电、扳手或标签，在链路中间标出“入口 / 触发 / 影响 / 修补”。

### Agent 编排

适合：Codex、Claude、Cursor、多 agent、skills、hooks、MCP、自动化协作。

画法：把 agent 系统画成一张低科技调度台、线缆交换机、邮局分拣台或小型控制室。黑色操作员不是老板，而是在插线、换路由、检查 hook 是否触发。

### 证据栈

适合：可信度、调研、复盘、文章论证、不是拍脑袋。

画法：一叠证据纸、日志条、截图碎片或实验样本被黑色操作员一块块铺成桥、墙、楼梯或秤盘。强调“证据搭出来”，不要画成空泛信任图标。

### 前后对比

适合：混乱/有序，手动/自动，分散/收拢，焦虑/稳定。

画法：左混乱，右稳定，中间橙色箭头。角色可以更夸张。

### 角色状态

适合：用户痛点、创作者状态、工具太多、信息焦虑、卡住到跑起来。

画法：2-4 个小状态，每个状态一个短标注。

### 概念隐喻

适合：内容工厂、信息仓库、脑内黑盒、工作流机器、自动日报。

画法：一个大的怪物件或机器，少量输入，一个输出。要有记忆点。

### 方法分层

适合：方法论框架、系统层级、能力栈、内容系统分层。

画法：一层层盒子，不要正式金字塔；黑色操作员在旁边搬砖或搭建。

### 地图路线

适合：从想法到上线、用户路径、内容承接路径、学习路线。

画法：一条弯曲路径，少量节点，黑色操作员牵线或走路。

### 小漫画分镜

适合：失败到成功、真实过程、吐槽、使用前后变化。

画法：2-4 个小场景，每格只表达一个动作。

## 原创隐喻生成法

每次都从当前文章重新发明隐喻，不能照搬旧图。

### 三步

1. 把抽象概念换成一个物理动作：卡住、漏掉、变重、分拣、沉淀、发酵、开门、折叠、拆包、回流。
2. 把系统结构换成一个低科技物件：坏掉的机器、纸箱、抽屉、水管、邮筒、怪表盘、秤、井、梯子、奇怪工位。
3. 让黑色操作员承担动作：不是站旁边，而是卡在机器里、拉错线、守门、搬运、修补、称重、扶梯子、记录、把东西塞进某个怪装置。

### 可用物件池

- 纸箱、抽屉、旧机器、漏斗、秤、邮筒、门、井、梯子、水管、线团、闸门、转盘、黑盒、打孔器、压面机、晾衣绳、怪工位。
- 日志纸带、漏洞门锁、证据钉板、工具插排、hook 捕鼠夹、MCP 小邮局、submodule 货架、版本齿轮、沙箱玻璃罩、风险水闸。
- 用时只选 1-2 个，不要堆满。

### 黑色操作员动作池

- 拉、扛、塞、捞、压、称、缝、剪、拧、守、推、接、拆、标记、回收。
- 看日志、钉证据、接线、拔错线、修 hook、给风险贴红标、把 skill 装进盒子、用小扳手拧版本齿轮。
- 动作要服务核心意思，不要为了怪而怪。

## 反复刻规则

不要默认打开或复刻 `assets/examples/`。这些图片只用于风格校准，例如线条密度、留白、颜色克制、角色气质。

除非用户明确说“照这张 / 复刻这个构图 / 用这个案例改”，否则不要直接复用这些旧构图：

- 传送带两个断点
- 黑色操作员在内容机器里拉判断杆
- 黑色操作员变漏斗分拣流量/信任/转化
- 黑色操作员切素材鱼
- 黑色操作员牵承接路径
- 黑色操作员拉三层信息源
- 三个黑色操作员分别拿喇叭/搭桥/开门
- 黑色操作员盖章话术工具箱
- 黑色操作员举牌看常见坑路径

同类主题也要换新隐喻。例如“承接路径”不一定画路线，可以画黑色操作员把内容尾巴接到门把手；“一鱼多吃”不一定画鱼，可以画黑色操作员把一个纸团压成几种形状；“漏洞链路”不一定画黑客，可以画它在漏水管道上给证据贴标签。
